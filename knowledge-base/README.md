# База знаний по услугам «Пиксель Плюс»

Материалы с https://pixelplus.ru/ для гибридного поиска (BM25 + векторы), как у ассистента сайта портфолио.
В базу входят страницы услуг, кейсы (`/portfolio/…` и кейсы внутри разделов услуг) и страницы о компании (`/studio/…`).
Не входят статьи и видео (`/samostoyatelno/`, `/stati/`, `/studio/stat/`), новости, команда, вакансии, СМИ и публикации.

## Состав

- `scripts/crawl.py` — обход сайта по ссылкам (sitemap у сайта нет) с соблюдением `robots.txt` и паузой 1 с.
  Сырой HTML сохраняется в `raw/` (в Git не входит). Повторный запуск продолжает с места остановки.
- `scripts/extract.py` — очистка HTML в Markdown: убирает шапку, подвал, меню, формы, кнопки и призывы оставить заявку.
  Блоки, повторяющиеся на трёх страницах и более, выносятся в `_obshchie-bloki.md` раздела
  (или в `kb/company/obshchie-bloki.md`, если они встречаются в разных разделах).
  Почти одинаковые страницы одного каталога (например, «Продвижение сайтов в <городе>») сводятся к одной:
  в базу идёт одна страница с разделом «Варианты этой страницы», где перечислены остальные.
  Страницы почти без текста (кейсы из одних картинок) в базу не берутся.
- `excluded.json` — что не попало в `kb/`: страницы без текста и свёрнутые варианты.
- `urls.json` — все найденные адреса: что взято, куда перенаправило, что пропущено и почему.
- `index.json` — список файлов базы с адресом, заголовком, типом, разделом и объёмом.
- `kb/services/<раздел>/`, `kb/cases/<раздел>/`, `kb/company/` — Markdown, по файлу на страницу.
  В начале каждого файла: `url`, `title`, `kind`, `section`, `description`, `crawled_at`.

## Гибридный поиск

Устроен как у ассистента сайта портфолио: поиск по словам (BM25) и по смыслу (векторы Workers AI `@cf/baai/bge-m3`
в Cloudflare Vectorize, индекс `pixelplus-services`), списки объединяются методом взаимного ранга (RRF).

- `search/search-text.mjs` — нарезка Markdown на куски (по заголовкам, 1 200–4 000 знаков, большие таблицы по группам
  строк с повторённой шапкой) и термины BM25 с русским стеммингом. Перенесено из портфолио
  (`src/worker/chat/search-text.ts`) с одним отличием: короткий хвост раздела присоединяется к соседнему куску,
  иначе база не помещается в бесплатные 5 млн хранимых измерений Vectorize (портфолио уже занимает 1,56 млн).
  Этот же модуль должен использовать будущий Worker, чтобы куски и термины совпадали.
- `search/build-index.mjs` — пишет `search-index.json`: документы, границы кусков, индекс BM25 и `corpus` (хеш базы).
  `--check` проверяет, что индекс соответствует текущему `kb/`.
- `search/embed-index.mjs` — эмбеддинги кусков и загрузка в Vectorize с метаданными `kind`, `section`, `corpus`
  (`--create` при первом запуске создаёт индекс и индексы метаданных для фильтра по `kind` и `section`).
  Перед загрузкой проверяет бесплатный объём хранения. Токен — `CLOUDFLARE_API_TOKEN` из окружения
  или из `.env` сайта портфолио (тот же аккаунт Cloudflare).
- `search/search-cli.mjs` — проверка: `--verify` (куски покрывают все документы без пропусков) и пробный поиск
  `"вопрос" [--vectors]`.

После каждого изменения `kb/`: `build-index.mjs`, затем `embed-index.mjs`. Если кусков стало меньше,
лишние старые векторы остаются в Vectorize — их надо удалить или пересоздать индекс.

## Запуск

Нужны Python 3.12, `requests`, `beautifulsoup4`, `lxml`, `markdownify`. Команды выполняются из корня проекта:

```sh
python -I knowledge-base/scripts/crawl.py
python -I knowledge-base/scripts/extract.py
```

`extract.py` каждый раз пересоздаёт `kb/` целиком из `raw/`.

Индекс поиска (Node.js 22, внешних пакетов не нужно; на этой машине Node лежит в `S:\NoDejs\node.exe`):

```sh
node knowledge-base/search/build-index.mjs
node knowledge-base/search/embed-index.mjs
node knowledge-base/search/search-cli.mjs "сколько стоит продвижение интернет-магазина" --vectors
```
